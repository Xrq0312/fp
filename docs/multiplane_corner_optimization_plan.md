# Multi-plane and corner optimization plan

## Baseline audit

The preserved baseline is tag `baseline/original`. Its active path is
`src/edge_aware_plane_extract.cpp`:

1. Dense points are collapsed into one fixed 0.5 mm surfel grid.
2. KNN PCA estimates one normal and curvature per surfel.
3. A hard normal jump marks an edge-like surfel.
4. Low-curvature seeds grow greedily through the 26-neighbor graph. A surfel is
   owned by the first accepted patch and is not reconsidered during proposal
   generation.
5. Similar patches are greedily merged. One synchronous boundary pass can
   transfer a surfel only to a label already found in its 26-neighborhood.
6. Dense points are assigned using plane distance, a rectangular 2-D envelope,
   nearby surfel ownership, and optionally the local normal.
7. Corners are generated by enumerating all plane triples and retaining
   intersections with dense and per-plane radius support.

The baseline is strong on dense, clean CAD exports, but has five structural
limitations:

- one spatial/normal scale suppresses fine faces and makes thresholds tied to
  sampling density;
- greedy, exclusive proposal generation makes the result order-dependent;
- the single local competition pass has no model cost or persistent outlier
  label, so it cannot reliably correct over-segmentation and model competition;
- a Boolean edge flag and rectangular support envelope do not describe the
  actual boundary of a face;
- global direction families only relax merging; they do not jointly refine
  parallel or orthogonal planes. Corner enumeration is cubic in patch count and
  does not require three observed pairwise boundaries.

## Fusion architecture

The implementation is staged. Every stage is selectable from the CLI and every
stage includes all earlier stages, so an ablation is a real executable path and
not a reconstruction from Git history.

| Variant | Added mechanism | Main reference idea |
| --- | --- | --- |
| `baseline` | frozen original path | repository baseline |
| `multiscale` | global pass plus adaptive fine residual proposals; deterministic oriented three-surfel hypotheses | CPFN, Efficient RANSAC, Minimal Quadric Fits |
| `joint` | alternating multi-label assignment/refit, label cost, model birth/death/merge | Progressive-X, PEARL |
| `topology` | observed adjacency, one-sided plane support, and conservative dense boundary correction | SED-Net, Progressive-X |
| `boundary` (planned) | continuous multi-scale boundary confidence | SED-Net |
| `--parallel-relations soft|hard` | complete-link parallel relation discovery and centroid-preserving normal refinement; explicit prior only | GlobFit |
| `--corner-mode adjacency` | observed finite intersections, graph-local triples, SVD conditioning, and two-branch support | SED-Net, GCCao validation pattern |
| `--edge-residual-proposals` | unexplained persistent-boundary proposals, model-birth benefit, and local occupied support | CPFN, Progressive-X, SED-Net |

The neural components of CPFN and SED-Net are not copied: no training data or
GPU runtime is introduced. Their transferable principles are used instead:
global/local cascades, explicit boundary evidence, and surface-edge feedback.
Likewise, the three-oriented-point and repeated-validation pattern is adapted to
plane proposals; this project does not currently detect cylinders.

## CPU-oriented design

- Dense points are only traversed for voxelization and final assignment.
- Proposal, competition, and relation optimization operate on surfels.
- Spatial neighborhoods use the existing integer grid; no all-pairs graph is
  built.
- Fine-scale work is restricted to unexplained, high-residual, or boundary
  neighborhoods selected by the coarse/global pass.
- Hypotheses are deterministic for reproducibility. Candidate scoring is lazy:
  cheap normal/distance tests precede connectivity and envelope validation.
- Joint labeling uses bounded ICM-style coordinate descent over local candidate
  labels. It implements the PEARL energy terms without adding a graph-cut
  dependency to the CPU build.
- Corner candidates come from triangles in the plane adjacency graph rather
  than all `O(P^3)` triples.
- The dominant large-cloud wall time is PLY parsing/serialization rather than
  joint labeling. `--binary-plane-output` preserves the colored result exactly
  while avoiding tens of seconds of ASCII formatting; ASCII remains the
  compatibility default.

## Evaluation protocol

Two kinds of evidence are kept separate:

1. Deterministic synthetic fixtures provide plane instance labels. The stepped
   box covers small faces, internal openings, and corners; intersecting planes
   with noisy dense edge bands measure boundary spill. Report plane
   precision/recall, macro IoU, coverage, over-segmentation, corner
   precision/recall/error, and runtime.
   A deliberately non-parallel 0.8-degree fixture is a guard against treating
   geometric proximity as proof of a parallel/orthogonal design relation.
2. `top_left_cut` and `top_down` are scan regression datasets without checked-in
   instance ground truth. Report coverage, patch count, fragmentation proxies,
   edge/corner counts, fit RMS, deterministic repeatability, and CPU time; raw
   counts must not be described as accuracy or recall.
3. `top_left_cut2` and `top_down2` are clean CAD samples corresponding to
   `data2.STEP` and `data1.STEP`, respectively. In addition to plane-equation
   checks, extract vertices incident to three distinct STEP planes and use
   one-to-one matching for corner precision, recall, F1, and localization error.
   Coincident but disconnected STEP faces must not be collapsed when future
   plane-instance GT labels are generated. The implemented finite-face evaluator
   parses outer and inner STEP loops (including circular annuli), labels clean
   CAD samples, constructs a prediction/truth IoU matrix, and uses one-to-one
   Hungarian matching to report precision, recall, F1, macro IoU, oversegmentation,
   and undersegmentation.

Acceptance priorities are: (1) no regression in synthetic plane/corner recall,
(2) reduced false merge and fragmentation, (3) higher real-data coverage, and
(4) bounded CPU cost. A stage is not enabled by default until it passes its
ablation against all available datasets.
